# AI 集群诊断：双 Worker 对照演示

## 演示目标

展示 AI 集群诊断不是分析单个任务，而是对同一服务的多个实例并行采集、
建立健康对照，并根据跨节点差异定位故障范围。

## Web 操作

1. 打开 `https://192.168.10.10/`，进入“AI 集群诊断”。
2. 点击“载入双 Worker 演示”。
3. 确认范围中包含：
   - `dual-worker-1` → `linux-worker-1` → PID `1`
   - `dual-worker-2` → `linux-worker-2` → PID `1`
4. 点击“开始诊断”。
5. 在“运行进度”中观察系统完成范围解析、证据规划、双节点受控采集、
   证据归一化和跨节点归因。

## 预期现象

- worker1：采集完成，结构化系统指标证据可用。
- worker2：Agent 在线并执行采集，但证据上传到对象存储失败。
- 诊断会话：`COMPLETED`，不是将探针失败简单视为诊断失败。

## 预期结论

- 跨节点判断：`单节点对象存储链路异常`
- 根因位置：`目标自身 · dual-worker-2`
- 问题领域：`网络 · Worker 到对象存储的连接异常`
- 根因候选：`对象存储上传链路异常`
- 判断置信等级：`高`

双节点对照表应显示：

- `dual-worker-1`：`DONE`、结构化证据可用
- `dual-worker-2`：`FAILED`、证据上传失败

## 真实原因

控制虚拟机存在一条定向防火墙规则，只拒绝：

`192.168.10.12 → 192.168.10.10:9000`

因此 worker1 能访问同一个 MinIO，worker2 不能。健康节点构成反证，可排除
MinIO 整体宕机，并把故障范围收敛到 worker2 的定向网络、防火墙或 endpoint
链路。

## 演示后恢复

```bash
sudo /home/control/mini-drop-demo/storage_link_fault.sh recover
```
