## 环境

- Control：`192.168.10.10`，4 vCPU，5924 MiB；
- worker1：`192.168.10.11`，4 vCPU，3914 MiB，Agent `linux-worker-1`；
- worker2：`192.168.10.12`，4 vCPU，3914 MiB，Agent `linux-worker-2`；
- Online Boutique：v0.8.0，11 个应用服务和 Redis，共 12 个 Swarm 服务；
- 离线镜像包：487777280 字节，两台 Worker 的 SHA-256 均为 `16faae2255ed376fa4f595a7820870775bf266bc317adb9a241143542c8f61db`。

入口：`http://192.168.10.11:8080`。worker2 的 8080 端口也通过 routing mesh 返回同一服务。

## 破坏性测试

- 网络分区：iptables 规则写入前建立 25 秒自动回滚定时器；两轮均恢复；
- 磁盘耗尽：在 512MiB loopback ext4 文件系统中两轮写到 100%，后续写入得到 `ENOSPC`；卸载删除后根盘仍为 18%；
- Control 重启：重启 Server 和 Analyzer 后 2.17 秒恢复 API；两个 Agent 回到 ONLINE；历史诊断仍可读；重启后 process scan 为 DONE。

## 未覆盖项

- 两台 Worker 位于同一台物理 Hyper-V 主机，未覆盖物理故障域隔离；
- 当前环境没有请求指标和分布式 Trace，延迟场景主要依赖系统指标、Profile 和日志；
- VM 仍无法直连官方镜像仓库，后续部署需继续使用校验过的离线镜像包或内部镜像仓库。
