# Mini-Drop 真实链路核验结论（2026-08-21）

## 结论

本次有两条真实链路完成：8 个真实 GitHub PR 各执行一轮 DeepSeek
归因，以及从单个 PID 出发的未知拓扑发现与受控 Pi 调查。两条链路都使用
`deepseek-v4-flash`，不是规则输出、投影预览或本地模型模拟。

PR 样本人工评分为 75/80（93.75%）。该结果证明当前链路在这 8 个样本的
一次运行中能完成机制级归因、处理反证并控制影响边界；它不是自动评分，
也不代表多轮稳定性或正式产品准确率。

未知拓扑最终轮次为 `PASS`。Agent 从唯一给定的 client PID 发现同机 TCP
server，形成 2 个节点、1 条依赖边，并从 client/server 两个观察点复核。
由于 macOS `lsof` 无法提供 Linux netns、cgroup 和 socket inode，覆盖结论
保持 `insufficient_coverage`，Agent 只确认通信依赖并拒绝把它写成因果根因。

不能替代云厂商网卡计费口径。

## 未知拓扑真实 Pi 链路

最终轮次验证了以下闭环：

1. Control 接受真实 Pi Runtime Turn，Sidecar 产生并记录 DeepSeek completion。
2. `discover_topology` 从种子 PID 发起受预算约束的一跳发现。
3. 依赖图持久化为 2 个节点、1 条边，client/server 两端均有观察。
4. 对新发现 server 仅执行一次低风险复核采集，并绑定 discovery run、
   membership snapshot、当前 revision、进程 incarnation 与权威 Evidence。
5. 三份投影 digest 一致，Runtime event sequence 连续且身份唯一。
6. 结论写入 SQLite，因覆盖不完整而明确 abstain，不把 TCP 连接当作根因。

最终结果包含 4 条 Case Evidence、13 个运行时事件；所有验收布尔项为真。
本地 Agent/Analyzer artifact upload 均关闭，轮询间隔为 5 秒。macOS `nettop`
只能提供进程聚合采样，且不能独立核算 provider 侧上传，因此拓扑轮次不声明
精确总上行字节；provider prompt 是已知且必要的外部上传。

## 能力边界

当前 Agent 已展示：机制级代码归因、Evidence/反证引用、在证据不足时 abstain、
从未知 PID 扩展依赖图、跨采集轮次维持实体身份与 revision 权威、把观察图和
因果图分离，以及在低带宽模式下复用投影并关闭非必要 artifact 上传。

仍需改进的是 canonical Evidence 引用精度。未知拓扑轮次只证明本机一跳 TCP
发现和边界控制；NAT、负载均衡、代理后端、跨主机 Linux netns/cgroup 身份和
短连接漏采仍需在对应环境分别验证。
